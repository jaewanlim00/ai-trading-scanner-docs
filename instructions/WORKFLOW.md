# GPT Work 작업 규칙

## 기본 원칙

- 이 저장소는 `ai-trading-scanner`의 작업 지시와 운영 문서를 공유하는 저장소다. 코드 저장소와 혼동하지 않는다.
- 최신 지시서와 현재 상태를 먼저 읽고, 지시서에 적힌 대상·범위·검증 기준만 수행한다.
- 소스 코드는 별도의 명시적 지시가 있을 때만 변경한다.
- 기존 파일, 사용자 변경, 설정을 임의로 초기화하거나 삭제하지 않는다.
- 모호한 규칙은 추측해 확정하지 않는다. 독립적으로 진행 가능한 작업은 이어가고, 결정이 필요한 사항은 미해결 항목으로 보고한다.

## 프로젝트 경계

- 대상 코드 프로젝트: `C:\Users\PC1\ai-trading-scanner`
- 다른 프로젝트에는 접근하거나 수정하지 않는다.
- 작업 전 현재 Git 상태와 대상 파일을 확인한다. 이미 존재하는 변경 사항은 보존한다.
- 파일 생성·수정은 지시된 범위 안에서만 한다. 삭제는 명시적으로 허용된 경우에만 한다.

## 사전 승인이 필요한 작업

다음 작업은 문서나 작업 지시에서 구체적으로 승인되지 않았다면 먼저 승인을 요청한다.

- 패키지 설치, 제거, 버전 변경 등 의존성 변경
- 환경변수, API 키, 인증정보 변경 또는 새 비밀값 설정
- 데이터베이스 스키마 변경, 마이그레이션 적용, 데이터 삭제·초기화
- 외부 서비스 설정 변경, 배포, 공개
- 승인된 프로젝트 경계를 벗어나는 작업
- 되돌리기 어렵거나 파괴적인 작업

승인된 범위의 일반적인 파일 수정·생성, 빌드, 테스트, 오류 수정은 매 단계마다 확인을 요청하지 말고 연속해서 수행한다.

## 거래소·데이터 보안

- 거래소 공개 시세 데이터만 사용한다. 개인 거래소 키와 자동주문 기능을 추가하지 않는다.
- `.env`, `.env.local`, 비밀키, 비밀번호, Supabase Service Role Key를 문서나 Git에 기록하지 않는다.
- Supabase 비밀값은 승인된 환경변수/비밀 저장소에서만 관리한다. 로그와 보고서에는 값이 아니라 설정 여부만 표시한다.
- 거래소 작업은 사용자가 시작한 분석 요청에 한정한다. 승인 없이 cron, 24시간 감시, 자동 반복 실행을 추가하지 않는다.

## 작업 및 검증 순서

1. 최신 지시, 이 규칙, `handover/STATUS.md`, 관련 설계 결정을 읽는다.
2. 현재 파일과 Git 변경 상태를 확인하고 대상 파일을 기록한다.
3. 필요한 변경을 최소 범위로 수행하며 기존 동작을 보존한다.
4. 코드 변경이 있으면 프로젝트에서 지정한 빌드·테스트를 실행한다. 문서 전용 변경은 코드 빌드가 불필요하면 생략 사유를 기록한다.
5. API·DB·외부 서비스 검증은 실제 실행 결과와 제한 사항을 구분해 보고한다. 미실행 검증을 성공으로 표현하지 않는다.
6. 완료 후 `reports/`에 작업 보고서를 작성하고 `handover/STATUS.md`를 갱신한다. 확정된 설계가 바뀌었을 때만 `decisions/`에 기록한다.
7. 변경 파일, 핵심 변경, 빌드·테스트 결과, 미해결 항목, 다음 작업을 보고한다.

## Git 사용

- 작업 대상 저장소와 브랜치를 먼저 확인한다.
- 지시가 main 반영을 명시한 경우에만 승인된 문서 변경을 main에 반영한다.
- 다른 변경이 섞였거나 충돌이 있으면 덮어쓰지 말고 상태를 보고한다.
- 커밋에는 해당 지시 범위의 파일만 포함한다.
