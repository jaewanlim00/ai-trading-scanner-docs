# 설계 결정 기록 규칙

AI Trading Scanner의 주요 설계 원칙과 확정된 결정을 기록합니다.

- 분석 대상 및 거래소 범위
- 롱·숏 분석 원칙
- 분석 시간봉과 지표
- 후보 선정 기준
- 데이터 수집 및 저장 방식
- 보안 및 운영 원칙

확정되지 않은 매매 규칙은 임의로 확정하지 않습니다.

## 기록 방법

확정된 결정을 이 파일에 날짜와 함께 추가하거나, 결정이 독립적이고 길면 `decisions/YYYY-MM-DD-short-topic.md` 파일로 기록합니다. 기존 결정을 조용히 바꾸거나 삭제하지 않습니다. 변경·대체 결정에는 이전 결정을 연결하고 이유를 적습니다.

각 결정에는 다음을 포함합니다.

- 상태: 제안 / 확정 / 대체 / 폐기
- 결정 날짜와 결정 주체 또는 승인 근거
- 맥락과 해결하려는 문제
- 선택한 내용과 고려한 대안
- 영향받는 코드·데이터·운영 영역
- 검증 및 후속 작업

사용자가 승인하지 않은 값이나 분석 규칙은 제안 상태로만 기록합니다. API 키와 비밀값은 기록하지 않습니다.

## 현재 확정된 기준

- 거래소: Binance, OKX, Bybit 공개 시세
- 시장 범위: USDT 결제 선형 무기한 계약만 포함하며 현물, Coin-M, inverse, 옵션은 제외
- 분석은 사용자가 화면의 시작 버튼을 눌렀을 때만 수행
- 1h, 4h, 1d 종료 캔들을 기준으로 하며 초기 수집 목표는 시간봉별 500개
- 롱과 숏은 독립적으로 평가하고 한 종목이 양쪽 결과에 모두 포함될 수 있음
- 개인 거래소 키, 자동주문, 정기 cron, 상시 모니터링은 추가하지 않음
- 원형파·후잔잔의 세부 판정 규칙은 아직 확정되지 않아 방향 신호에 임의로 사용하지 않음
- Supabase는 별도 프로젝트를 사용하고 환경변수로만 접속
